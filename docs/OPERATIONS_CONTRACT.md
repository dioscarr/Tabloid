# Tabloid operations contract

Cross-repository source of truth for Podman, Tailscale, preview deployment,
secrets, and service ownership.

## Repository ownership

| Runtime surface | Repository | Primary contract |
| --- | --- | --- |
| Admin UI and Admin API | `.` | `compose.yaml`, `api/`, `scripts/`, `tailscale/` |
| App Gallery | `Tabloid/Tabloid-app-gallery` | `compose.yaml`, `src/`, `scripts/`, `tailscale/` |
| Other static apps | `Tabloid/<app>` | app `compose.yaml`, `Containerfile`, preview scripts |
| Brain | `../Tabloid-brain-production` | `services/brain/`, `compose.yaml`, `tailscale/` |
| Dashboard | `../Tabloid-dashboard` | `src/`, `compose.yaml`, `tailscale/` |
| Main Production | `../Tabloid-main-production` | `compose.yaml`, production/preview scripts |

Always edit and commit in the owning repository and its existing named branch.
Do not create or use `workspace/*` branches unless explicitly requested,
created manually, or generated by App Gallery provisioning.

## Common Podman pattern

Most app repositories define a `tabloid` web container on port `8080` and a
`tabloid-tailscale` userspace sidecar. The web container is health-checked at
`http://127.0.0.1:8080/`; the sidecar depends on that health check and requires
`TS_AUTHKEY` from the runtime secret store. `TS_CERT_DOMAIN` selects the HTTPS
hostname.

Main Production is different: it uses external networks
`my-web-stack_default` and `tabloid-data-platform`, plus the external volume
`my-web-stack_tabloid-tailscale-state`. Do not recreate those resources
casually.

## Tailscale routing

Each repository keeps its route template in `tailscale/serve.json`. The common
desired route is:

```text
HTTPS :443 -> http://tabloid-app:8080
```

Admin and preview gateway variants may use generated destinations such as the
static gateway or `__TABLOID_SERVE_DESTINATION__`. The deployer resolves
placeholders before applying the config. A route is healthy only after the
public Tailscale hostname and the app health endpoint both respond.

## App Gallery provisioning

```text
App Gallery
  -> POST /api/v1/applications/provision
  -> Admin API authorization + CSRF + idempotency
  -> persisted app-provision request/event
  -> asynchronous provisioning worker
  -> branch/build/preview deployment
  -> Tailscale preview route
```

The browser never receives GitHub, Podman, or Tailscale credentials. Admin API
owns templates, authorization, persistence, and provisioning. Brain may provide
analysis/context, but it does not own App Gallery branch creation.

## Secrets and runtime state

Keep in the host/secret store, never in Git: Tailscale and GitHub credentials,
Admin/Brain service tokens, private `.env` files, Podman machine state,
containers, networks, volumes, and generated runtime state.

Keep in Git: compose files, Containerfiles, Tailscale templates, deploy/sync/
verify/recovery scripts, safe `.env.example` variable names, and runbooks.

## Reconciliation checklist

1. Identify the owning repository and existing named branch.
2. Check Git status and recent history there.
3. Compare compose/Tailscale declarations with live Podman/Tailscale state.
4. Verify container health, sidecar connectivity, HTTPS, and API health.
5. For Gallery, inspect persisted provisioning requests/events and worker logs.
6. Apply the smallest reversible correction and rerun the verify script.
7. Record commit SHA, image tag/digest, hostname, and verification time.

Repository configuration is desired state. Podman and Tailscale are runtime
state that must be inspected and reconciled, not committed wholesale.
